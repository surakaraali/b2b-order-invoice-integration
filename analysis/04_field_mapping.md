## 1. Purpose and conventions

This document defines every field that crosses a system boundary in the three flows: what it is called in each system, its type, whether it is mandatory, how it is validated and how it is transformed. The OpenAPI specification and the UBL-TR mapping in the integration service are built from these tables, and the Postman tests use the same names and limits.

**Conventions**

| Convention | Rule |
|---|---|
| API field names | JSON, camelCase, UTF-8, for example `dealerOrderNo` |
| Mandatory | **M** mandatory, **O** optional, **C** conditional (the condition is given in the table) |
| Dates | `YYYY-MM-DD`, Türkiye calendar date |
| Timestamps | ISO 8601 with offset, for example `2027-03-05T14:21:07+03:00` |
| Quantities | JSON number, up to 3 decimals; whole numbers for piece units |
| Amounts | JSON number, 2 decimals, half-up rounding, currency `TRY` |
| Strings | Trimmed; a value longer than the maximum is rejected, never truncated |
| Enumerations | Upper case with underscores, listed in section 8 |
| SAP Business One | Table.Field, for example `OPOR.DocNum` (purchase order header), `POR1.ItemCode` (purchase order line), `OPCH`/`PCH1` (A/P invoice), `OCRD`/`CRD1` (business partner, addresses), `OSCN` (supplier catalogue numbers), `U_` prefix for user-defined fields |
| Logo (Tiger, Go) | Table.Field without the company and period prefix, for example `ORFICHE.FICHENO` for `LG_001_01_ORFICHE.FICHENO`; `ORFICHE`/`ORFLINE` (orders), `INVOICE`/`STLINE` (invoices), `CLCARD` (business partner), `SHIPINFO` (shipping addresses), `ITEMS` (items), `UNITSETL` (units) |
| UBL-TR | XPath relative to the `Invoice` root, namespaces `cbc` (basic) and `cac` (aggregate), UBL-TR 1.2 |
| Direction | Each table states its source and target |

## 3. Order request

Direction: dealer ERP or portal to the API. Message: body of `POST /orders`.

### 3.1 Headers

| Header | M/O | Format | Validation | Notes |
|---|---|---|---|---|
| `Authorization` | M | `Bearer <access token>` | Valid, unexpired OAuth2 token bound to a dealer | Client credentials grant, token lifetime 1 hour |
| `Idempotency-Key` | M | UUID v4 | Unique per dealer for 7 days | Repeat returns the original response (RULE-10) |
| `Content-Type` | M | `application/json` | | |
| `Accept-Language` | O | `tr` or `en` | | Language of `reasonText` and error messages, default `tr` |

### 3.2 Header fields

| API field | Type | M/O | SAP Business One (OPOR) | Logo (ORFICHE) | Portal form | Validation | Notes |
|---|---|---|---|---|---|---|---|
| `dealerCode` | string(10) | M | Connector configuration | Connector configuration | Taken from the user's dealer | Must equal the dealer of the token | See section 2 |
| `dealerOrderNo` | string(30) | M | `OPOR.DocNum` | `ORFICHE.FICHENO` | Generated: `P-YYYYMMDD-NNNN` | Unique per dealer | Echoed in every event |
| `orderDate` | date | M | `OPOR.DocDate` | `ORFICHE.DATE_` | Today | Not in the future, not older than 30 days | |
| `requestedDeliveryDate` | date | O | `OPOR.DocDueDate` | Earliest `ORFLINE.DUEDATE` | Date picker | Not before `orderDate` | Informational in this version; no promise is made |
| `deliveryAddress` | object | M | Address of `OPOR.ShipToCode` in `CRD1` (AdresType `S`) | `SHIPINFO` record of the order | Selected from saved addresses | See section 3.3 | |
| `dealerNote` | string(500) | O | `OPOR.Comments` | `ORFICHE.GENEXP1` | Free text | | Shown to the sales representative, not to the warehouse |
| `lines` | array | M | `POR1` rows | `ORFLINE` rows | Order grid | 1 to 200 lines, no repeated `sku` | Repeated SKUs are rejected with `DUPLICATE_LINE_SKU` |

### 3.4 Line fields

| API field | Type | M/O | SAP Business One (POR1) | Logo (ORFLINE) | Portal form | Validation | Notes |
|---|---|---|---|---|---|---|---|
| `lineNo` | integer | M | `POR1.LineNum + 1` | `ORFLINE.LINENO_` | Row number | 1-based, contiguous | Echoed in events and in UBL `OrderLineReference` |
| `sku` | string(20) | M | `OSCN.Substitute` looked up by `POR1.ItemCode` | `ITEMS.PRODUCERCODE` of `ORFLINE.STOCKREF` | Chosen from the catalogue | Active in the catalogue and in the dealer's price list (RULE-02) | |
| `dealerItemCode` | string(50) | O | `POR1.ItemCode` | `ITEMS.CODE` | Not used | | Echoed back only |
| `quantity` | decimal(12,3) | M | `POR1.Quantity` | `ORFLINE.AMOUNT` | Quantity field | Greater than 0; whole number for piece units; at least the minimum order quantity (RULE-04) | |
| `unitCode` | string(3) | O | `POR1.UomCode` mapped to UN/ECE | `UNITSETL.CODE` of `ORFLINE.UOMREF` mapped to UN/ECE | Shown, not editable | Must equal the SKU's sales unit; defaults to it | Section 8.4 |
| `dealerLineRef` | string(30) | O | `POR1.LineNum` | `ORFLINE.LOGICALREF` | Not used | | Echoed back only |

Not accepted in the request: prices, discounts, VAT, totals. Prices come from the dealer's price list on the Vektör side (RULE-03) and are reported back in the status event.

## 9. Transformation rules

| ID | Rule |
|---|---|
| T1 | Dates from dealer systems are taken as Türkiye calendar dates; times are not sent in the order. Event timestamps are produced in `+03:00`. |
| T2 | Quantities are rounded half-up to 3 decimals. For piece units (`C62`, `SET`) a non-integer quantity is rejected with `QUANTITY_NOT_INTEGER`. |
| T3 | Line net amount = round(quantity × unit price, 2) minus line discount. Line VAT = round(line net × rate ÷ 100, 2). Document VAT per rate = sum of the line VAT amounts at that rate, never recomputed from the totals, so that the UBL-TR consistency checks pass. |
| T4 | Strings are trimmed. A value longer than the maximum is rejected at the API with `FIELD_TOO_LONG`; nothing is truncated. Turkish characters are kept as UTF-8 in JSON and in UBL. |
| T5 | Delivery address: `addressLine1` to `StreetName`, `addressLine2` to `BuildingName`, `district` to `CitySubdivisionName`, `city` to `CityName`, `postalCode` to `PostalZone`, `countryCode` `TR` to `Country/Name` `Türkiye`. |
| T6 | SKU cross-reference is kept in the dealer ERP (SAP Business One supplier catalogue numbers, Logo producer code). The connector translates before sending; the API accepts only Vektör SKUs. The portal needs no cross-reference. |
| T7 | Line numbers are 1-based and contiguous in the request; the same numbers are used in events, in the UBL `OrderLineReference` and in the invoice event. |
| T8 | Invoice numbers follow the GİB format of 3 letters, 4-digit year and 9-digit sequence; the series `VKT` is reserved for dealer invoices. |
| T9 | Status values are written to the dealer ERP as text in a user-defined field; the connector decides whether a status also changes the ERP's own document status (for example closing the purchase order when `CLOSED`). |
| T10 | `Idempotency-Key` values are compared case-insensitively after trimming; a value that is not a UUID is rejected with `INVALID_IDEMPOTENCY_KEY`. |
| T11 | Unit codes from dealer systems are mapped to UN/ECE codes with the table in section 8.4; an unmapped unit is rejected with `INVALID_UNIT`. |
